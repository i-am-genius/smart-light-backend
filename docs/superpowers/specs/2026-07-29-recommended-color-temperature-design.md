# 服装主色推荐色温算法设计

## 背景

`MainColorServiceImpl` 根据识别出的服装主色计算推荐亮度和色温。当前工作区中的色温公式存在两个相反阶段的问题：

- 旧公式偏移幅度过小，实际服装颜色的推荐值大量集中在约 4000K。
- 当前公式用两个余弦之差计算 `warmScore`，其绝对值可接近 2，却配合 1800K 的最大偏移使用；同时色度在 `chroma = 25` 时就达到满幅，导致粉色、红色、橙色等大量撞到 2700K 下限。

本次调整需要扩大不同颜色间的有效差异，同时避免粉色被当成极暖红橙色。

## 研究依据

不存在 CIE 或 IES 标准化的“物体 RGB 到推荐照明色温”公式。CIE 的相关色温定义用于从光源的光谱或色度计算最接近的黑体辐射温度，而不是根据被照物颜色选择照明。

本设计采用以下研究结论约束自定义推荐模型：

- 面料实验中，4000K 白光整体偏好较高，4700K 偏粉白光与多种面料配色的匹配度较高。
- 蓝色牛仔服装实验中，约 5500K 同时获得较高的颜色偏好与辨别能力。
- 跨物体实验表明，光源本身对照明偏好的影响通常大于单个被照物体颜色，因此不应仅凭主色把色温推向设备上下限。
- 显色忠实度和颜色偏好还受光谱、照度及显色指标影响，单一 CCT 推荐只能作为现有硬件能力下的启发式控制。

参考资料：

- CIE CCT 定义：https://cie.co.at/eilvterm/17-23-068
- Kim 与 Suk 的面料照明研究：https://doi.org/10.1002/col.22537
- 蓝色牛仔服装照明实验：https://doi.org/10.1177/1477153518816125
- 跨物体照明偏好实验：https://doi.org/10.1177/1477153517713542
- CIE 颜色质量指标立场声明：https://doi.org/10.25039/PS.6qdfenyc

## 目标

- 常见粉色推荐值稳定落在 4200–4600K，不再落到 2700–2800K。
- 饱和红橙色、蓝色等能够形成明显且合理的色温差异，不再都集中在约 4000K。
- 颜色间连续变化时，推荐值连续变化，不在色相分类边界突然跳变。
- 黑白灰和低饱和颜色回归中性基准值。
- 不修改接口、WebSocket 消息、设备协议或 ESP 固件。

## 非目标

- 不把该算法描述为标准色彩科学公式。
- 不处理灯具光谱、Duv、CRI、CIE Rf 或 IES TM-30 指标；当前设备协议只提供色温控制。
- 不根据面料类别修改本次主色映射。现有 `GarmentRecognitionProcessor` 中的面料微调保持不变。
- 不扩大到真实照片数据集拟合；后续可用人工标注数据替换锚点。

## 算法

### 颜色空间

沿用现有 sRGB 到 CIELAB 的转换，使用：

- `h = atan2(b*, a*)` 得到 0–360° 的色相角；
- `C* = sqrt(a*² + b*²)` 得到色度。

CIELAB 色相角与常见 HSV/HSL 色相角不同，锚点必须按照当前转换函数的实际输出定义。

### 中性基准与饱和度权重

中性基准色温为：

```text
T_base = 4200K
```

色度权重采用平滑阶跃，避免低饱和颜色受不稳定色相影响：

```text
C* <= 8:   s = 0
C* >= 50:  s = 1
其他情况:
  x = (C* - 8) / 42
  s = x² × (3 - 2x)
```

因此黑白灰和低饱和颜色返回 4200K；颜色越鲜明，越接近对应色相锚点。

### 色相锚点

在圆环上按相邻锚点做线性插值：

| CIELAB 色相角 | 代表色 | 满色度目标 |
|---:|---|---:|
| 0° | 粉色 | 4400K |
| 40° | 红色 | 3600K |
| 75° | 橙色 | 3500K |
| 105° | 黄色 | 4000K |
| 140° | 绿色 | 4400K |
| 200° | 青色 | 5000K |
| 306° | 蓝色 | 5500K |
| 330° | 紫色/品红 | 5000K |
| 360° | 粉色，闭合点 | 4400K |

最终计算为：

```text
T = round(T_base + s × (T_hue - T_base))
T = clamp(T, 3500K, 5500K)
```

0° 与 360° 使用相同目标值，保证环形边界连续。粉色位于品红到红色之间，但锚点会把它保持在中性略暖范围，而不是沿红橙方向降到极暖色温。

## 数据流与兼容性

数据流保持不变：

```text
图片
  → MainColorServiceImpl 提取主色
  → 计算推荐亮度与主色色温
  → GarmentRecognitionProcessor 应用现有面料微调
  → 聚合多件服装结果
  → REST/WebSocket 返回现有 recommendedTemp 字段
```

只修改 `MainColorServiceImpl` 内部色温计算。方法签名、响应字段和设备上下行协议均不变。

现有面料微调可能使最终结果略超出主色算法的 3500–5500K 区间，例如羊毛减去 250K；最终结果仍由现有 2700–6500K 防御性范围限制。这是现有业务规则，本次不改。

## 错误处理

- 图片无法解析、无有效像素或聚类失败时，继续使用现有默认结果，不改变异常兼容行为。
- 非彩色或接近非彩色的主色不依赖色相角，直接回归 4200K。
- 算法最终保留 3500–5500K 限制，避免数值误差或锚点插值产生极端推荐值。

## 测试设计

新增 `MainColorServiceImplTest`，通过内存生成纯色图片调用公开的 `extract` 方法，覆盖真实主色提取到推荐值的完整路径，不通过反射测试私有方法。

至少覆盖：

- 浅粉、粉色、热粉、深粉均位于 4200–4600K。
- 红色和橙色明显低于粉色，并位于 3500–3900K。
- 蓝色位于 5200–5500K 附近，且明显高于粉色。
- 灰色等低饱和颜色回归 4200K。
- 所有代表色输出均位于 3500–5500K。
- 无效图片仍返回现有默认结果。

测试先以当前公式运行并确认粉色用例因返回 2700–2800K 而失败，再实现最小修改使其通过。最后运行目标测试、全部测试和 `mvnw compile`。

## 成功标准

- 典型粉色色块不再产生 2700–2800K 推荐。
- 代表颜色覆盖约 3500–5500K 的有效动态范围。
- 锚点间没有硬分类分支造成的明显跳变。
- 新增测试、现有测试及项目编译全部通过。
